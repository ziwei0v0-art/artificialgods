# 天姥桌宠基础可玩 MVP 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 superpowers:executing-plans 逐项实现本计划。每项先建立可失败的行为测试，再实现最小代码并验证。

**目标：** 约 8 小时内交付一个 Mac 上可运行、可完成“招虫—活动／繁殖—抓虫—入瓶—放回或出售—买并摆放陈设—存档恢复”的基础可玩版本，并单独说明桌面常驻和正式美术是否完成。

**架构：** 游戏规则、存档和控制面板使用 Python 标准库与 Tkinter；macOS 桌面常驻主体由 Swift/AppKit 透明置顶窗口绘制，通过本机 JSONL 标准输入输出与 Python 控制器同步虫群、接收捕捉/移动/缩放等事件。原生可执行文件编译到用户 Application Support，不污染项目。角色先用符合已确认轮廓的简化程序绘制临时素材，任何占位都不得冒充定稿。

**技术栈：** Python 3.12、Tk 9.0、Swift/AppKit、标准库 `unittest`、`json`、`pathlib`、`tempfile`。

**规格：** `神龛桌宠_MVP主体迭代稿_v0.4_文字整合版_20260924.md`，特别是第 3、4、5、6、9、10 节及附录 A。

## 全局约束

- 延续“天姥”称谓和 v0.4 规则；唯一活人道童是灰黑肤、白发束小髻露额、红瞳长尖耳、素黑道袍白内领、普通布腰带、无冠。
- 天姥是六臂、长尖耳静态供像；任何临时绘制不得画成活人或动画角色。
- 桌面个体、瓶内个体、已售个体状态互斥；放回必须恢复同一只虫及其性别、体色和遗传信息。
- 虫瓶可按体色与性别选择；有交易副作用的动作一次性提交；出售钱款准确到账；虫谱发现不因出售而清除。
- 自动积攒满 24 小时只停止自动捕捉；手动捕捉继续。成功出售或放回至少一只后清零并恢复自动捕捉，剩余库存保留。
- 游戏关闭／休眠暂停游戏模拟，不补离线收益；倒计时按真实经过时间计算，二者分开。
- 桌面层使用 AppKit borderless、clear background、floating、all Spaces 与默认 click-through；只有捕捉/移动/缩放模式短时接收鼠标，松手或 Esc 恢复穿透。实机鼠标、系统睡眠仍需单独验收。
- 不改动原始 PDF、DOCX、ZIP 或美术参考；不接入外部服务、不上传素材、不切换图像模型或 API。

## 验收重点与已知风险

- 交易期间新抓到个体不能被并入当前交易批次；零数量、取消、查看和预览不能触发副作用。
- AaBb × AaBb 的子代以两个独立位点遗传，不把 9:3:3:1 错当每批必然配比。
- 隐藏窗口、睡眠或重启不能凭离线时长生成虫、繁殖、捕捉或额外收益。
- 24 小时边界和部分库存放回后的重置需用可控时钟测试，不能等待真实 24 小时。
- Tkinter 8.5 在当前 Mac 可导入；实际视觉与窗口行为仍需打开应用复核。
- 图像服务根因仍未知；正式美术不纳入本次玩法闭环的阻塞项。

## 文件职责与接口

- `tianmu_mvp/model.py`：纯业务状态和规则；`GameState.new(rng=...)`、`advance(seconds)`、`catch(ids)`、`release(color, sex, count)`、`sell(color, sex, count)`、`buy(item_id)`、`place(item_id)`、`process_seconds(seconds)`。
- `tianmu_mvp/storage.py`：`load_state(path)` 与 `save_state(path, state)`，负责版本字段、校验、原子写和错误回报。
- `tianmu_mvp/drawing.py`：仅程序绘制；不保存或覆盖参考美术；可替换素材从模型独立。
- `tianmu_mvp/ui.py`：Tkinter 主场景、四页、输入事件和可见状态，不直接修改模型内部结构。
- `main.py`：解析可选 `--save-file`，载入／初始化状态，启动应用，便于隔离测试档。
- `tests/test_model.py`：游戏规则、交易和计时边界。
- `tests/test_storage.py`：持久化往返、原子替换失败及损坏输入。
