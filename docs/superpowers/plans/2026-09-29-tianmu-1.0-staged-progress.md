# 天姥 1.0 分阶段推进与验收

唯一工程目录：`<PROJECT_ROOT>/`

本计划落实用户已授权的持续推进：每轮只做一件有实际价值的工作；检查间隔约 10 分钟，当前 Chat 出图阶段只读查看，生成中不追加消息。已有负责人使用 Codex 任务「核对天姥桌宠codex」，美术由 Chat「设计捉宠游戏」提供。不得新建重复任务、重复生成同一素材或重做已通过的核心闭环。

## 目标和停止条件

把现有工程推进到可交付的当前 Mac 版 1.0：必要美术能被工程读取并在桌宠实际尺寸正确显示；核心玩法及必要界面连贯；自动回归和可运行构建通过；证据与未完成的实机边界写入 `1.0进度与验收.md`。达到这些条件就冻结。非阻断装饰、额外动作和无明确价值的审美润色进 1.1。

流程验收和自动化测试不能代替用户的真实鼠标／睡眠唤醒体验；未实测的项目明确留待用户验收，不伪称完成。

## 节奏规则

1. 当前 Chat 修图时，每 10 分钟只读检查一次该对话状态；未完成就不发新消息、不重复唤醒。若对话已完成，立即检查回执，下载/导入前确认文件确实能被本机读到，再进入阶段1验收。
2. 任何阶段收到新成果即做对应验收；通过则当轮把唯一下一步交给现有 Codex 负责人并更新进度记录。检查周期不是等待理由，阶段完成后立即推进。
3. 每次检查都回答三个问题：新增了什么可核验产物？本阶段门槛是否通过？下一件具体工作是什么？没有变化时保持安静，不重复写状态汇报。
4. 对同一阻断最多进行两轮有证据的修复；仍失败则保留失败样例、说明阻塞和可行替代，避免无限打磨。素材交付通道不通时，允许并行推进与它无依赖的必要界面／工程验收，但不可用占位图冒充正式美术通过。
5. 不启动第二个演示实例，不覆盖正式存档，不调用新图像生成渠道；不发布、签名、上传或申请权限。所有涉及美术的判断必须实际打开原图并按游戏显示尺寸核查。

### 2026-09-30 桌面虫层与一次拖拽织网可行性检查点（137）

结论：独立、覆盖屏幕、位于普通应用下面且鼠标穿透的虫群层，有公开API支持，可以进入实现；“同一个无修饰空白拖拽，既只织网又完全保留Finder框选”存在无法从相同输入判断意图的冲突，不能承诺自动两全。不是macOS不能做织网，而是需要明确手势起点或模式。

本轮仅读当前项目源码、已有复用记录、已安装Apple SDK公共头文件及官方文档。没有取得或审阅WindowServer私有实现，不把SDK声明称作WindowServer源码。没有启动窗口/worker、运行候选、申请权限、访问存档、修改产品或生成美术。GitHub固定提交页面及API本轮读取失败，DesktopFly结论沿用已记录的2026-09-25评估，不冒称重新验证上游源码。

| 问题 | 有证据的边界与决定 |
|---|---|
| 虫群独立于桌宠 | 现有 `native/v1/main.swift:526` 只建一个 `.floating` 场景，虫坐标在 `OverlayHost.swift` 中映射到540×380局部画布。需独立虫群窗口，不能只放大原神龛窗口或改其level。神龛移动/缩放不得再带动虫群。 |
| 桌面下层显示 | `CGWindowLevel.h:22–68` 提供desktop/desktopIcon/normal等级与取值接口。候选用 `CGWindowLevelForKey(.desktopIconWindow)+1`，保持低于normal；这是依据等级关系提出的实现选择，不是Apple提供的桌宠示例。虫可画在图标前但不挡图标点击。用 `NSScreen.frame` 覆盖显示器，不调用系统全屏切换；非key/main、常态 `ignoresMouseEvents=true`；Spaces/Expose采用桌面型行为，不能照搬当前fullScreenAuxiliary。壁纸、Stage Manager、全屏应用下的实际可见性仍需实机验证。[Apple窗口等级](https://developer.apple.com/documentation/coregraphics/cgwindowlevelkey)、[鼠标穿透](https://developer.apple.com/documentation/appkit/nswindow/ignoresmouseevents?language=objc)。 |
| 普通空白拖拽旁听 | 全局NSEvent监听只收到异步副本，不能阻止Finder原动作。因此可伴随画网，但会同时出现Finder框选，也可能在整理图标时误捕虫；不推荐默认启用。若让整张虫层接收输入，又会遮住Finder操作。[Apple事件监听](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/MonitoringEvents/MonitoringEvents.html)。 |
| 判断桌面空白 | 前台Finder仅说明键盘目标，不能证明鼠标在桌面。公开windowNumber命中查询能排除穿透窗口，比矩形猜测好，但只返回窗口，不能据此保证区分同一Finder桌面内图标与空白，更不能判断一次空白框选的意图。全局主动过滤还涉及权限与投递风险，本轮不采用、不作免权限保证。[Apple窗口命中查询](https://developer.apple.com/documentation/appkit/nswindow/windownumber(at:belowwindowwithwindownumber:))；SDK `NSWindow.h:634`、`NSEvent.h:541–543`。 |

推荐最小可玩切片及后续顺序（顺序固定，手势起点待协调确定）：

1. 先做独立虫群层：首个验收覆盖当前主屏整张桌面，继续使用现有后台个体/自动捕获/虫瓶接口。把 `drawInsects` 和虫位置渲染从 `TianmuView` 分离，`store.onState` 分别路由；虫层绝不变为整屏输入遮罩。设置默认“仅桌面”，另可选“显示在应用上方”，只改虫层。此步用户即可观察到“窗口盖住苍蝇、神龛拖动不带虫走”的实际差异，不依赖织网取舍。
